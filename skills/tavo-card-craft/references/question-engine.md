# 问答引擎（双通道）

> 本文件定义角色卡制作前的信息收集流程。提供 basic-mode（3 问出卡）与 pro-mode（深度问答）双通道。

## 一、模式选择

收到生成请求后，**第一句话**先判断模式（标准见 `task-routing.md` 第五部分），不确定时直接问用户：

> "要快速版（3 问出卡）还是深度版（完整问答）？"

不要默认走完整问答，那是 v2.2.2 之前的反模式。

## 二、basic-mode（快速通道，3 问出卡）

适用：用户给一句话描述、要求快速出卡、原型验证。

### 问题清单（只问这 3 个）

**Q1. 角色核心**
> "一句话描述这个角色是谁？（例如：傲娇学姐、末日幸存者、修仙师妹）"

**Q2. 互动基调**
> "希望互动偏哪种？A 暧昧撩拨 / B 战斗冒险 / C 日常养成 / D 剧情解谜"

**Q3. 视觉风格**
> "卡面风格偏哪种？A 极简文字 / B 卡片化信息面板 / C 沉浸式氛围 / D 玩法 HUD"

### 生成规则

- 收到 3 个回答后**立即生成**，不再追问。
- 默认采用 `visual-style-guide.md` 第6节 中对应范式的标准 CSS。
- 三件套（description / first_mes / alternate_greetings）必须齐全。
- first_mes 控制在 800-1500 字，alternate_greetings 给 2-3 个变体。
- 生成后必须跑 `validate_card.py`。

### basic-mode 禁止事项

- ❌ 不要问世界观细节（用默认设定填充）
- ❌ 不要问状态系统（basic-mode 默认无状态）
- ❌ 不要问遮罩需求（basic-mode 默认无遮罩）
- ❌ 不要问扩展标签（basic-mode 默认纯文本）

如果用户在 Q1-Q3 中主动补充了细节，可以采纳，但不要因此追加问题。

## 三、pro-mode（深度通道，完整问答）

适用：用户要求深度定制、玩法卡、状态卡、遮罩卡、多 greeting 卡。

### 阶段 1：角色骨架（3 问）

**Q1. 角色身份与背景**
> "角色的姓名、身份、年龄、核心背景故事？越详细越好。"

**Q2. 性格与说话方式**
> "性格关键词 3-5 个？说话风格（语气、口头禅、用词习惯）？"

**Q3. 与用户的关系设定**
> "角色和用户（player）是什么关系？初始好感度/态度？"

### 阶段 2：世界观与玩法（2-4 问，按需）

**Q4. 世界观设定**
> "故事发生在什么世界？有无特殊规则（魔法/科技/末日/修仙体系）？"

**Q5. 玩法机制**（仅当用户提到玩法时）
> "需要哪些玩法？A 状态系统（生命/好感/资源） / B 探索地图 / C 战斗回合 / D 物品背包 / E 任务系统 / F 其他"

**Q6. 互动目标**
> "用户玩这张卡的终极目标是什么？通关条件 / 养成目标 / 剧情结局？"

### 阶段 3：视觉与交互（2-3 问）

**Q7. 视觉范式**
> "参考 `visual-style-guide.md` 第6节 的 5 种范式，选哪种？或描述你想要的视觉感觉。"

**Q8. 遮罩需求**（仅当涉及弹窗/覆盖层时）
> "需要遮罩吗？什么场景触发？（战斗结算 / 事件弹窗 / 系统菜单 / 物品查看）"

**Q9. 状态持久化**（仅当有状态系统时）
> "状态怎么存？A 每次对话自动存 / B 手动存档点 / C 多槽位存档 / D 不需要持久化"

### 阶段 4：扩展与细节（1-2 问，按需）

**Q10. 扩展标签**
> "需要自定义标签吗？（例如 `<status>` `<map>` `<combat>` 等游戏化标签）"

**Q11. 多 greeting**
> "需要几个开场变体（alternate_greetings）？每个的差异化方向？"

### pro-mode 生成规则

- 每个阶段问完即可进入下一阶段，不必全部问完。
- 用户在某阶段说"不用了"或"够了"立即停止追问。
- 阶段 2-4 的问题按需触发，不强制全问。
- 生成前最后确认一次："以上信息我整理成卡，确认开始生成？"
- 生成后必须跑 `validate_card.py` + `render-checklist.md` 自检。

## 四、问答通用规则

1. **一次只问一个阶段**：不要把 11 个问题一次性抛出，按阶段递进。
2. **提供选项**：能用 A/B/C 选项的就用选项，减少用户输入成本。
3. **接受模糊回答**：用户说"差不多就行"时，用默认值填充并告知。
4. **记录关键决策**：每个回答都在内部记录，生成时逐条对照不遗漏。
5. **允许中途切换**：basic-mode 进行中用户要求深度定制，可升级到 pro-mode 补问。
6. **禁止过度追问**：单次任务总问题数 basic ≤ 3，pro ≤ 11，超出说明需求未明确，应让用户先想清楚。

## 五、默认值表（用户未回答时填充）

| 字段 | basic-mode 默认 | pro-mode 默认 |
|------|-----------------|---------------|
| 世界观 | 现代都市 | 按用户阶段 2 回答 |
| 状态系统 | 无 | 按用户阶段 2 回答 |
| 视觉范式 | B 卡片化信息面板 | 按用户阶段 3 回答 |
| 遮罩 | 无 | 按用户阶段 3 回答 |
| 持久化 | 无 | A 自动存 |
| 扩展标签 | 无 | 按用户阶段 4 回答 |
| greeting 数 | 1 个 | 3 个 |
| first_mes 长度 | 800-1200 字 | 1500-3000 字 |
