---
description: 自动更新 MCP、工具和 skill（支持 --check 仅检查模式，单组件失败自动降级跳过）
---

自动检查并升级 opencode 生态的各个组件。**opencode 本体只检测版本、不自动升级**（Windows 上运行中的 exe 无法替换，升级需重启后进行）。

## 参数

| 参数 | 说明 |
|------|------|
| (无) | 检查并升级（默认） |
| `--check` | 仅检查，列出可升级项，不实际执行升级 |

## 环境判断

先判断当前环境，只执行当前环境适用的部分：
- 笔记本（Windows）：`$env:OS` 含 "Windows" 或存在 `C:\`
- 软路由（Linux）：`uname` 返回 Linux

<!-- laptop-only -->
笔记本版：以下「一~四」为 Windows 环境逻辑；「四-b 软路由 oc 更新」需在笔记本上通过 `ssh router` 操作软路由。
<!-- /laptop-only -->

<!-- router-only -->
软路由版：本命令在软路由上执行时，跳过「一~四」的 Windows 逻辑（无 exe/npm 全局包），只执行「四-b」的 Docker 重建流程（在软路由本机直接执行，无需 ssh）。
<!-- /router-only -->

## 执行流程

<!-- laptop-only -->
### 一、升级前备份

`git diff` 确认当前配置变更，关键配置（`opencode.jsonc`、`AGENTS.md`）复制到 `Temp\opencode\` 备份，确保出问题能回滚。

```powershell
Copy-Item "C:\Users\pass\.config\opencode\opencode.jsonc" "$env:TEMP\opencode\opencode.jsonc.bak-$(Get-Date -Format yyyyMMdd-HHmmss)"
```

> 原 `backup.ts` 插件已移除，不再依赖。

### 二、逐组件检查/升级（按序执行）

> `--check` 模式：每步仅检查版本并报告"可升级/已是最新/跳过"，不执行实际升级命令。
> 正常模式：每步检查后若有新版则执行升级，失败则报告"已跳过：原因"并继续下一组件，不阻塞全流程。

**1. windows-mcp（uv 工具）**
```bash
uv tool upgrade windows-mcp
```

**2. npm 全局包（非 opencode 本体）**
```bash
npm install -g @playwright/mcp@latest superpowers-mcp@latest ctx7@latest
```

**3. context7 本地包（~/.config/opencode/node_modules）**
```bash
npm install --prefix ~/.config/opencode @upstash/context7-mcp@latest
```

**4. npx 类 MCP**（tavily / firecrawl）：每次启动自动拉最新，无需处理，跳过。

**5. remote MCP**（exa / github）：云端维护，跳过。

**6. Skill 自动更新**（多来源对比 + 自动下载，备份后覆盖）：

**6a. superpowers 更新**：
```bash
# 查本地版本
node -e "console.log(require('C:/Users/pass/.config/opencode/node_modules/superpowers/package.json').version)"
# 查 GitHub 最新（需代理）
$env:HTTPS_PROXY="http://Clash:****@192.168.3.100:7893"; gh api repos/obra/superpowers/tags --jq '.[0].name'
```
- 有新版 → `npm install --prefix ~/.config/opencode git+ssh://git@github.com/obra/superpowers.git`
- 更新后重启 opencode 生效
- **降级**：`gh api` 失败（如代理/网络问题）→ 报告"已跳过：gh api 失败"并继续，不阻塞后续

**6b. SkillHub skill 更新**：
```bash
# 搜索 SkillHub 上的 skill（返回 version）
curl.exe --noproxy "*" -s "https://lightmake.site/api/v1/search?q=<skill名>"
# 下载 skill（返回 zip 包）
curl.exe --noproxy "*" -sL "https://lightmake.site/api/v1/download?slug=<slug>" -o <skill>.zip
```
- 对比本地 `_meta.json` 的 version 与 SkillHub 最新 version
- 有新版 → **先备份本地 skill**（复制到 `Temp\opencode\`）→ 解压 zip 覆盖 `skills/<name>/`
- 本地自定义 skill（agent-reach、humanizer、opencode-maintenance、steam-tools、tavo-*、userscript、clash-subscription-management、self-improving-agent）**不自动覆盖**，只报告差异（避免覆盖本地定制）
- **降级**：`curl` 失败 → 报告"已跳过：SkillHub 不可达"并继续

**6c. clawhub skill 更新**：
```bash
# 检查 clawhub 是否有新版本
clawhub search self-improving-agent  # 返回版本信息
# 或直接更新
clawhub update @pskoett/self-improving-agent
```
- 对比本地 `_meta.json` 的 version 与 SkillHub 最新 version
- 有新版 → **先备份本地 skill**（复制到 `Temp\opencode\`）→ 执行 `clawhub update` → 验证 `skills/self-improving-agent/SKILL.md` 版本号
- **降级**：`clawhub` 失败 → 报告"已跳过：clawhub 不可达"并继续
- **本地定制保护**：agent-reach、humanizer、opencode-maintenance、steam-tools、tavo-*、userscript、clash-subscription-management、self-improving-agent**不自动覆盖**，只报告差异（避免覆盖本地定制）

**6d. 输出报告**：已更新（组件 + 旧版本 → 新版本）/ 已是最新 / 跳过（本地定制/网络失败）。

### 三、验证

每步升级后立即验证（失败则回滚该组件，不影响其他）：
- `opencode --version`（当前版本仍正常）
- `uv tool list` / `npm ls -g --depth=0`（确认新版本号）
- 关键 MCP（windows-mcp / context7）能启动

### 四、opencode 本体检测（不自动升）
```bash
npm view opencode-ai version   # 最新版
opencode --version             # 当前版
```
- 若 `最新 > 当前`：提示「opencode 有新版本 X，重启 opencode 后再运行 /更新 即可升级」
- 若相同：提示「opencode 已是最新版」
<!-- /laptop-only -->

<!-- router-only -->
### 四-b、软路由 oc 更新（Docker 容器，可选执行）

笔记本的 opencode 是 exe 无法热升，但**软路由 opencode 是 Docker 镜像，可完整升级**。仅当 `npm view opencode-ai version` 大于软路由当前版本时执行。

**1. 查软路由当前版本与镜像**：
```bash
ssh router "docker exec opencode opencode --version; docker images | grep opencode-arm64"
```

**2. 下载新二进制并重建镜像**（在软路由上执行，`/root/oc-build/` 已有 Dockerfile）：
```bash
# 下载对应版本 linux-arm64 二进制（替换 VERSION）
curl -sL --noproxy '*' -o /root/oc-build/opencode.tar.gz "https://github.com/anomalyco/opencode/releases/download/opencode-v{VERSION}/opencode-linux-arm64.tar.gz"
cd /root/oc-build && tar -xzf opencode.tar.gz && mv opencode-linux-arm64 opencode && rm opencode.tar.gz
docker build -t opencode-arm64:{VERSION}-full /root/oc-build
```
> ⚠️ Dockerfile 必须保留 apt 工具层（curl wget git jq ca-certificates openssh-client unzip python3 procps），否则容器内 ssh/scp/curl 全丢（LRN-20260811 事故）

**3. 高可用重建容器**（关键，避免 stop→rm→run 窗口期无服务）：
```bash
# 先以新镜像起临时容器名，验证 OK 后再切换
docker run -d --name opencode-new --restart always -p 4097:4096 \
  -v /etc/opencode:/root/.config/opencode \
  -v /etc/opencode/data:/root/.local/share/opencode \
  -e OPENCODE_ENABLE_EXA=1 \
  -e OPENCODE_EXPERIMENTAL_PLAN_MODE=1 \
  -e OPENCODE_SERVER_PASSWORD=<密码> \
  -e EXA_API_KEY=<key> -e GITHUB_PERSONAL_ACCESS_TOKEN=<token> \
  -e TAVILY_API_KEY=<key> -e CONTEXT7_API_KEY=<key> \
  -e FIRECRAWL_API_KEY=<key> \
  opencode-arm64:{VERSION}-full
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:4097   # 验证 200
docker stop opencode && docker rm opencode
docker stop opencode-new && docker rename opencode-new opencode
docker start opencode && docker rm -f opencode-new   # 清理
```
> 密码与 API key 从笔记本 User env 读取后 base64 经 `scripts/ssh_run.py` 传入（避免特殊字符转义，不落盘）；CONTEXT7 key 在笔记本 opencode.jsonc 明文里需手动带上（LRN-20260807）
> `/root/.ssh` 软链到 `data/ssh-backup/id_ed25519`（挂载卷持久），重建后自动恢复；旧镜像保留可回退

**4. 验证**：`ssh router "docker ps | grep opencode"` + 本机/Tailscale IP 4096 health 200。
<!-- /router-only -->

### 五、输出报告
简洁汇总：
- ✅ 已升级：组件名 + 旧版本 → 新版本
- ℹ️ 跳过：原因（本地定制/网络失败/已是最新）
- ⚠️ 需要操作：opencode 本体升级提示（如有）
- `--check` 模式额外标注"仅检查，未实际升级"

## 注意事项
- 不在会话运行中执行 `opencode upgrade`（Windows exe 锁，会 EBUSY 失败）
- 升级完成后写入 `.learnings/LEARNINGS.md`（按 `self-improving-agent` 技能格式，含 `upgrade` 标签 + `scope:` 环境标签）
- 若某组件升级失败，保留旧版本，报告原因，不强行升级
- **软路由容器重建**：勿直接 `docker stop/rm/run`（有窗口期无服务），用「新名起来→验证→切换」高可用流程；重建前完整备份 docker run 参数（env/挂载/端口）
- **降级原则**：单组件失败不阻塞全流程，每个组件独立报告成功/跳过/失败
