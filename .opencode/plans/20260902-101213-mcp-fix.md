## 0. 现象与已确认事实

### 现象
- TUI 底栏显示 `◎ 6 MCP /status` 红色，表示至少 1 个 MCP 启动失败或超时。
- `opencode-tray.log` 过去 36h 内 5 次 `serve crashed (exit=1)` 自动重启 + 全天 `reachable 0/1` 抖动（例：08:20–09:46 每 ~10min 抖一次）。
- `health-watchdog.log` 每 5min 一次 `12 CLOSE_WAIT on 4096 (possible SSE leak)` 并触发 `service status=Stopped, starting`（误判，实际端口仍 LISTEN）。

### 配置现状（`opencode.jsonc:146-231`）
| MCP | type | enabled | command / url | timeout | 状态 |
|-----|------|---------|---------------|---------|------|
| playwright | local | **false** | `npx -y @playwright/mcp --browser=chromium --headless` | 60000 | 已禁用，不计 |
| playwright-edge | local | true | `cmd /c npx -y @playwright/mcp --extension --browser=msedge` | 60000 | 风险最高 |
| context7 | remote | true | `https://mcp.context7.com/mcp` + `CONTEXT7_API_KEY` header | 20000 | 远程 |
| github | remote | true | `https://api.githubcopilot.com/mcp/` + `Bearer GITHUB_PAT` | 20000 | 远程 |
| tavily | local | true | `npx -y @mcptools/mcp-tavily` + `TAVILY_API_KEY` | 25000 | npx 缓存命中 |
| exa | remote | true | `https://mcp.exa.ai/mcp?exaApiKey={env:EXA_API_KEY}` | 25000 | 远程  |
| firecrawl | local | true | `npx -y firecrawl-mcp` + `FIRECRAWL_API_KEY` | 30000 | npx 缓存命中 |
| windows | local | true | `uvx windows-mcp` | 30000 | 本地 |
| comfyui | local | **false** | `python scripts/comfyui-mcp.py` | 60000 | 已禁用，不计 |

**计数**：enabled=7（edge+context7+github+tavily+exa+firecrawl+windows），截图显示 6，说明 TUI 可能未计 `windows` 或某一个启动失败后被剔除。需以 `/status` 为准。

### 环境已验证（只读探活）
- `HKCU\Environment` 8 个核心 key 全部存在（CONTEXT7/EXA/TAVILY/FIRECRAWL/GITHUB_PAT/PLAYWRIGHT_TOKEN/SERVER_PASSWORD/GO2）；`tray.cpp:115-129` `USER_ENV_VARS[13]` 注入 11/13，缺 2 个为 `HTTP_PROXY/NO_PROXY/GITHUB_TOKEN` 等非核心，不影响 MCP。
- `npm-cache\_npx\4e4233…` tavily、`12b05d…` firecrawl、`9833c…` playwright-mcp 缓存均存在；`uv tool list` windows-mcp v0.8.5 正常；`npm ls -g` 有 `@playwright/mcp@0.0.79`。
- `curl -w %{http_code} https://mcp.exa.ai/mcp` → 405，`https://mcp.context7.com/mcp` → 405，说明远程可达（MCP 是 POST-only，405=Method Not Allowed 为正常，网络/代理无阻断）。
- FlClash 本机代理 127.0.0.1:7890 存活，TUN 指向软路由 192.168.3.100，未见代理失联。

### 推断（待验证）
- **主因候选**：`playwright-edge` 扩展断连超时最常见（需 Edge 运行 + Bridge 扩展 + TOKEN 一致，`opencode.jsonc:160-167` 已配 `cmd /c npx` 绕过 ExecutionPolicy，见历史计划 `1788045020311-crisp-forest.md`）。
- **次因**：`windows` 的 `uvx` 首次冷启动慢（>30s 超时）或被防毒拦截；`tavily/firecrawl` 的 `npx -y` 在 serve 启动并发 7 个时抢带宽超时（历史 ERR-20260809-002）。
- **放大器**：7 个 MCP 并发初始化，任一 hang 会拖慢 serve 就绪，`tray` 15s 探活误判 `reachable=0` → `MaxRestart 3` 熔断，watchdog 又因 CLOSE_WAIT 反复 `Starting`，形成抖动循环。

## 1. 诊断（Phase 0 — 3 分钟，必须先做）

> 目标：拿到精确失败清单，再动手，避免盲改。

**步骤**：
1. **TUI 内**：按 `ctrl+p` → 输入 `/status` 或点底栏 `6 MCP`，截图/抄录每个 MCP 的 `state`（connected/failed/disabled）与 `error` 文本（尤其是 `playwright-edge` / `windows` 的超时或 ENOENT）。
2. **CLI**：`opencode mcp list --print-logs`（或 `opencode mcp list`）对比 TUI，确认失败数是否为 1/2/6 全红。
3. **日志**：`opencode-tray.log` 已看过，补充 `Get-Content "$env:LOCALAPPDATA\opencode\log\*.log" -Tail 100` 看 serve 侧 MCP stderr（是否有 `posix_spawn ENOENT` / `401 Unauthorized` / `ETIMEDOUT`）。
4. **快速自测（不改配置）**：
   ```powershell
   npx -y @mcptools/mcp-tavily --help 2>&1 | Select-Object -First 5
   npx -y firecrawl-mcp --help 2>&1 | Select-Object -First 5
   uvx windows-mcp --help 2>&1 | Select-Object -First 5
   # remote 鉴权探针（不发真实 MCP 请求，只验 key 非空）
   $env:CONTEXT7_API_KEY.Length; $env:EXA_API_KEY.Length; $env:TAVILY_API_KEY.Length
   ```

**产出**：一份 `MCP × 状态 × 错误原文` 表，决定进 Phase 1 哪个分支。

## 2. 隔离定位（Phase 1 — 二分法，5 分钟）

若 `/status` 显示多红或错误含混，用最小复现：

1. 备份：`Copy-Item opencode.jsonc "$env:TEMP\opencode\opencode.jsonc.bak-$(Get-Date -Format yyyyMMdd-HHmmss)"`
2. 临时将 7 个 enabled 全设 `enabled:false`，重启 TUI，确认 `0 MCP` 且 `reachable` 稳定（排除 serve 自身 crash）。
3. 二分回开：先只开 3 个 remote（context7/github/exa）→ 重启看是否绿；再加 2 个 npx（tavily/firecrawl）；最后加 2 个本地重型（playwright-edge/windows）。每轮记录 `reachable` 与 `MCP` 状态，定位到单个 offender。

## 3. 针对性修复（Phase 2 — 按 offender 类型）

### A. `playwright-edge` 超时（最常见）
- **检查**：Edge 是否运行（`Get-Process msedge`），扩展 `Playwright MCP Bridge` 是否启用且显示 Connected，`PLAYWRIGHT_MCP_EXTENSION_TOKEN` 与 `opencode.jsonc` 是否一致（当前 `HFKpow…` 已对上）。
- **修**：已是 `cmd /c npx -y @playwright/mcp --extension --browser=msedge`（绕过 `npx.ps1` ExecutionPolicy），若仍超时，改 `timeout: 30000→60000` 已是 60000 无需；尝试在 Edge 地址栏 `chrome://extensions` 重载扩展或重启 Edge；必要时临时 `enabled:false` 隔离。
- **验**：`playwright-edge_browser_tabs` 返回标签列表即绿。

### B. `windows` / `uvx` 失败
- **检查**：`uvx windows-mcp --help` 是否秒回；是否被火绒拦截（历史有 `windows-mcp` 需 `ANONYMIZED_TELEMETRY=false`）。
- **修**：若 ENOENT，`uv tool install windows-mcp` 或 `uv tool upgrade windows-mcp`；若超时，`timeout: 30000→60000`；若仍红，临时禁用（该 MCP 与 TUI 功能无强依赖）。
- **验**：`windows_*` 工具可用。

### C. `tavily` / `firecrawl` npx 超时
- **检查**：`npm-cache\_npx\*` 已命中，说明非缺包；看 serve 日志是否有 `ETIMEDOUT` / `fetch failed`。
- **修**：已用 `npx -y`，无需改；若并发超时，错峰：将 `tavily` `timeout 25000→40000`、`firecrawl 30000→45000`；或临时禁用一个观察 `reachable` 是否止抖。
- **验**：`tavily_search` / `firecrawl_search` 可用。

### D. `context7` / `exa` / `github` 远程鉴权失败
- **检查**：`curl -i -X POST https://mcp.context7.com/mcp -H "CONTEXT7_API_KEY: $env:CONTEXT7_API_KEY"` 看 401/200；`exa` 的 query 式 `?exaApiKey=` 是否被服务端拒（官方当前推荐 header `x-api-key`，需核对）；`github` 的 PAT 是否有 `copilot` 权限（普通 PAT 会 401，见 `github: oauth:false`）。
- **修**：
  - `context7`：若 401，核对 `CONTEXT7_API_KEY` 是否过期，重发 `https://context7.com/dashboard`。
  - `exa`：若 401，改 `opencode.jsonc:202-205` 为 `headers: { "x-api-key": "{env:EXA_API_KEY}" }` 并移除 URL query（需对照 https://mcp.exa.ai 文档）。
  - `github`：若 401，换 `gh auth token` 或在 `https://github.com/settings/tokens` 重签 PAT（需 `read:org, copilot` scope），或临时 `enabled:false`（不影响本地开发）。
- **验**：对应 MCP 工具列表出现。

### E. 代理/环境注入
- **检查**：`tray.cpp` `InjectUserEnv` 11/13 缺的 2 个是谁（对比 `HKCU\Environment` 与 `USER_ENV_VARS`），若缺 `HTTPS_PROXY` 导致 remote 走直连被 RST，则补齐。
- **修**：补 `USER_ENV_VARS` → `build-tray.bat` 重编译 → 重启托盘（见 `LRN-20260901-004` 同步脚本 `scripts/sync-env-to-tray.ps1 -Check`）。
- **验**：`tray.log` 下一次 `InjectUserEnv: 13/13`。

## 4. 回归与加固（Phase 3）

1. 全量 7 MCP 全绿后，重启 2 次（`Restart serve` 菜单 + 关开 TUI），确认 `reachable` 不再 10min 抖动，`health-watchdog.log` 的 `CLOSE_WAIT` 回落（历史为 SSE 泄漏，若仍 12+，另案处理，非 MCP）。
2. 写入 `.learnings/ERRORS.md`（若有新坑）或 `LEARNINGS.md`（若为配置更正），格式 `ERR-YYYYMMDD-XXX | Pattern-Key: mcp.<name>.<cause>`。
3. 若 `playwright-edge` 长期不稳定，考虑与 `playwright`（headless）二选一：日常用 `playwright`（隔离、无登录态），需登录态时再切 `playwright-edge`，减少并发。

## 6. 风险与回滚

- **风险**：改 `opencode.jsonc` 语法错误导致 serve 起不来；`uvx` 重装导致 windows-mcp 版本跳变。
- **回滚**：Phase 1 已备份 `opencode.jsonc.bak-*`；托盘可执行文件有 `*.bak-*`；`Copy-Item bak opencode.jsonc; Restart serve` 即可。
- **不做**：不动 `comfyui`（已禁用）、不动 `playwright`（已禁用）、不动软路由容器（本案仅笔记本）。
