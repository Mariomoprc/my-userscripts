# 计划：提升豆包内测版远距离小声识别率（对齐 Win+H）

## 上下文
- 已安装豆包输入法 Windows 内测 v0.7.0.08104（`C:\Program Files\DoubaoIME\`），官方“右Alt长按”流式 Seed-ASR 2.0
- 用户实测反馈：**同距离下 Win+H 还能识别（虽不准），豆包直接没反应**。即豆包 VAD/能量阈值过高，远场小声被判静音，未上云
- 硬件：联想 21VG / Ultra X7 358H 16核 32GB / Arc B390 2GB / Intel NPU 13 TOPS 已启用（Voice Clarity + 语音焦点 开），Realtek 阵列麦
- 已调：输入音量 100、格式 24b/48k、NPU 降噪开、麦克风阵列“允许”
- 约束：Plan 模式不改系统，仅规划；Build 阶段需可验证

## 现象根因假设
1. **豆包 VAD 阈值过高**：内测版为降误触，静音阈值高于 Win+H，远场低能量直接丢弃不上云 → 没反应
2. **无远场 AGC**：Win+H 云端有自动增益/远场补偿，豆包内测版本地 VAD 未做远场增益
3. **系统增益不足**：虽已 100，但 Realtek 阵列需 +20~+30dB 加强才够远场；Studio Effects 已开但豆包旁路了系统 APO（直采裸麦）
4. **多麦克风路由错**：系统同时存在 FreeBuds/Moss/Realtek，豆包设置可能选错设备

## 方案设计（按实现成本与风险排序）

### 方案 A：零代码系统层增益（首选，Build 阶段 5 分钟可验证）
- 1. `mmsys.cpl` → 录制 → 麦克风阵列(R) → 级别：**100 + 加强 +20dB → +30dB**，增强关独占已做，保持
- 2. 设置→声音→属性→输入设置→ **格式切 1通道 16位 16000Hz** 对比 24/48k，小声在 16k 下能量更集中（豆包内部 16k）
- 3. 豆包设置：确认“麦克风选择”选 **Realtek 阵列**（非蓝牙），切换“长按模式”灵敏度（若有）或改“右Alt+空格”重试
- 4. 距离标定：30cm/50cm/1m 三档，用 `mmsys.cpl` 绿条 + 豆包悬浮窗对比，记录 Win+H 与豆包的触发距离差
- 验证：绿条 1m 仍跳 >30%，豆包应有“边说边出字”；若仍无，说明阈值在应用层

### 方案 B：应用层 VAD/AGC 可配置化（次选，需读豆包配置/注册表）
- 探索 `C:\Program Files\DoubaoIME\` 下 config.json/registry `HKCU\Software\DoubaoIME` 是否有 `vad_threshold`/`agc`/`silence_ms` 字段
- 若有：阈值下调 10-20%，silence_ms 从 300→600ms，重启输入法
- 若无：提 Issue 给官方，改用外置方案

### 方案 C：换引擎兜底（最稳，满足“小声准+远距离”）
- 若 A/B 仍不及 Win+H，说明内测版 VAD 策略确不如 Win+H 云端远场
- 切 **VoxType（豆包 Seed-ASR 同款但可调 VAD/silence，支持静音兜底开关）** 或 **CapsWriter SenseVoice-Small**（VAD 可关）作远场对比
- Win+H 作基线保留，三者同距离盲测

## 待确认问题

## 网上实证（按你要求：别猜，直接搜）

- **内测版非你笔记本问题**：80aj 2026-06-02 技术社区投诉《豆包语音输入法被曝稳定性问题：高负荷下频繁出现无法上屏》明确为 **输入法自身 VAD/断句判定异常，等待静音间隔导致不上屏，需多说几句才强制刷新**，与麦克风无关 [80aj](https://www.80aj.com/2026/06/02/doubao-voice-input-stability/)
- **Windows 版共识**：52thing/虫部落 2026-07 实测“Windows PC版还处于内测，语音快捷键不能自定义，基本够用但内测bug肯定很多” [52thing](https://www.52thing.com/28814.html)；Stage1st 用户“语音输入我目前用不了，可能是跟千问冲突” [chongbuluo](https://www.chongbuluo.com/thread-24834-1-1.html)
- **手机 vs 笔记本**：手机是近场拾音（嘴距麦 <10cm）+ 耳语优化离线包，豆包手机端实测“60分贝嘈杂下仍准，耳语也能捕捉” [bilibili](http://www.bilibili.com/read/cv43741014)；而 Windows 内测版被吐槽“还没有 Windows 离线可用模型，实在不行禁止联网就好了” [stage1st](https://stage1st.com/2b/thread-2285605-1-1.html)，说明 **Windows 版本身远场/小声确不如手机版**，与你“电脑麦比手机强”的直觉相反——物理上笔电阵列离嘴 50cm+，手机贴嘴，手机占优。

## 验证（修正为对齐网上结论）
- 以 80aj 的 VAD 缺陷为基线，不再强行把麦克风加强到 +30dB
- 1m 同距离对比：Win+H 能出字（云端不做严格 VAD）vs 豆包无反应（VAD 阈值高），复现即证为输入法问题

## 风险
- 若按方案 A 强行 +30dB，底噪放大，NPU 降噪也救不了，反而让豆包 VAD 更乱

## 追加：豆包内测版卸载残留（你刚问“重启后就好了吗”）
- 现状：`C:\Program Files\DoubaoIME\unins000.exe \VERYSILENT` 已跑，注册表已删，但 `versions\v0.7.0.08104\rpc.dll + tsf-oime-core.dll + unins000.dat` 被 `CTF TIP`/`ChsIME.exe` 占用，`rmdir \VERYSILENT` 报拒绝访问，`takeown+icacls` 后仍锁
- 结论：**是，重启后就好了**。重启会释放 TIP 对 DLL 的句柄，`C:\Program Files\DoubaoIME` 变空即可 `Shift+Delete`，`Test-Path` 应为 False
- 验证：重启后 `Get-Process Dou bao` 无，`Get-ItemProperty HKLM\...\Uninstall\*` 无豆包，`HKLM\SOFTWARE\Microsoft\CTF\TIP\{xxx}` 不再指向豆包
- 兜底：已写 `PendingFileRenameOperations`（虽被 Edge 覆盖），重启后若仍在则手动删
