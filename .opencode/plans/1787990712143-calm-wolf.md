# Plan: 恢复毁灭性命令的确认弹窗

## 背景
- 用户希望 build/plan 尽量全自动（已将 `opencode.jsonc:3-8` 的 `permission` 改为全 `allow`）
- 用户补充：毁灭性操作仍需确认，不能裸奔

## 目标
- 日常命令（`git`, `tasklist`, `taskkill /IM TrafficMonitor.exe`, `Start-Process` 等）全自动不弹窗
- 毁灭性命令强制 `ask`（弹窗确认），避免误执行

## 变更
- **文件**: `C:\Users\pass\.config\opencode\opencode.jsonc:3-15`
- **操作**: 将 `permission.bash` 从
  ```jsonc
  "bash": { "*": "allow" }
  ```
  恢复/调整为：
  ```jsonc
  "bash": {
    "*": "allow",
    "rm -rf *": "ask",
    "del /s /q *": "ask",
    "format *": "ask",
    "shutdown *": "ask",
    "Remove-Item -Recurse *": "ask",
    "Clear-Content *": "ask"
  }
  ```
  - **说明**: 
    - 不再对 `taskkill /f *` 全局 `ask`，否则 TrafficMonitor 插件每次重启都会弹（截图场景）。如需更严，可改为精确规则 `taskkill /F /IM TrafficMonitor.exe*`: `allow`，其余 `taskkill /f *`: `ask`
    - `*`: `allow` 保证 plan/build 默认全自动

## 备选
- 更严格：上述 6 条改为 `deny`（直接禁止），但 `ask` 更符合“需要确认”的诉求
