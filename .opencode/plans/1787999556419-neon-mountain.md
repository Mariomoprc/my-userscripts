## 2. 需要优化的配置项

### 2.1 Compaction 配置更新 (高优先级)
**原因**: 当前使用 V1 配置格式 (`prune`, `tail_turns`)，但 opencode 已升级到 V2，使用新字段。

**当前配置**:
```json
"compaction": {
  "auto": true,
  "prune": true,
  "reserved": 20000,
  "tail_turns": 3
}
```

**建议更新为**:
```json
"compaction": {
  "auto": true,
  "keep": {
    "tokens": 20000
  },
  "buffer": 25000
}
```

**说明**:
- `keep.tokens`: 保留最近 20000 tokens 的上下文（原 reserved + tail_turns 的作用）
- `buffer`: 安全缓冲区，触发压缩的时机更早
- 移除 `prune` 和 `tail_turns`（V2 不再使用）

### 2.2 添加 Context Threshold 配置 (中优先级)
**原因**: 根据 GitHub issue #11314，长上下文模型 (如 MiMO V2.5) 在 75% context 时性能下降，建议提前压缩。

**建议添加**:
```json
"compaction": {
  "auto": true,
  "keep": {
    "tokens": 20000
  },
  "buffer": 25000,
  "token_threshold": 100000,
  "context_threshold": 0.50,
  "models": {
    "opencode-go/mimo-v2.5": {
      "context_threshold": 0.40
    }
  }
}
```

**说明**:
- 全局 context_threshold=0.50：在 50% context 时触发压缩
- MiMO V2.5 专用 threshold=0.40：更早压缩，保持性能
- 注意：此功能需要 PR #10123 合并后才能生效（当前未合并）

### 2.3 清理空的 Provider 白名单 (低优先级)
**原因**: `siliconflow-cn` 白名单为空，且无可用模型。

**建议**: 注释掉或删除该配置项
```json
// 硅基流动当前无免费对话模型，已禁用
// "siliconflow-cn": {
//   "whitelist": []
// },
```

### 2.4 添加 Snapshot 磁盘监控 (中优先级)
**原因**: 根据 GitHub issue #17397，snapshot 目录可能在 7 天内增长到 40GB+。

**建议添加环境变量**:
```json
"env": {
  "OPENCODE_EXPERIMENTAL_EVENT_QUEUE_MAX": "10000",
  "OPENCODE_SNAPSHOT_DAYS": "3"
}
```

**说明**: 将 snapshot 保留时间从默认 7 天缩短到 3 天，减少磁盘占用。

### 2.5 添加 Autoupdate 配置 (低优先级)
**原因**: 默认自动更新可能在不希望的时候更新。

**建议添加**:
```json
"autoupdate": "notify"
```

**说明**: 仅通知更新，不自动安装，避免工作中断。

### 2.6 添加 Small Model 配置 (低优先级)
**原因**: 对于轻量任务（如标题生成），使用更便宜的模型。

**建议添加**:
```json
"small_model": "opencode-go/deepseek-v4-flash"
```

**说明**: 使用 deepseek-v4-flash 处理轻量任务，节省成本。

## 3. 软路由优化建议

### 3.1 Docker 持久化 npm 包
**原因**: 当前 MCP npm 包安装在容器内，容器重建后需要重新安装。

**建议**: 将 npm 包目录挂载到持久化卷
```bash
docker run -d --name opencode \
  -v /etc/opencode/node_modules:/root/.config/opencode/node_modules \
  ...
```

### 3.2 添加 Docker 资源限制
**原因**: ARM64 设备资源有限，需要防止内存/CPU 过度占用。

**建议添加 Docker 资源限制**:
```bash
docker run -d --name opencode \
  --memory=512m \
  --cpus=1.5 \
  ...
```

### 3.3 定期清理 Docker 日志
**原因**: Docker 日志可能无限增长。

**建议配置日志轮转**:
```json
// /etc/docker/daemon.json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
```

## 5. 验证方法

1. **笔记本验证**:
   - 启动 opencode，检查无配置错误
   - 测试 plan/build agent 切换
   - 测试 MCP 服务器连接

2. **软路由验证**:
   - 检查容器状态：`docker ps | grep opencode`
   - 检查健康状态：`curl http://192.168.3.100:4096/global/health`
   - 测试 Web UI 访问

3. **磁盘监控**:
   - 定期检查 snapshot 目录大小
   - 监控 opencode.db 大小（警惕膨胀）

## 6. 注意事项

1. **配置合并**: opencode.jsonc 和 opencode.json 格式不同（JSONC 支持注释），同步时注意转换
2. **环境变量**: 软路由需要通过 docker run -e 或 .env 文件传递环境变量
3. **版本兼容**: 确保软路由和笔记本使用相同版本的 opencode
4. **备份**: 每次修改前备份配置文件
